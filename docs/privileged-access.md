# Ограниченный доступ к fanotify через sudo

Подготовлено для `roman`, UID/GID 1000, workspace `/home/roman/dlp-lab`.
Установка выполняется пользователем один раз с паролем в обычном терминале.
В этой сессии установщик не запускался, системные права не изменены.

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin /bin/bash /home/roman/dlp-lab/scripts/install-fanotify-access.sh
```

Установщик проверяет владельцев системных каталогов и исходную конфигурацию sudo,
собирает отдельную версию C-helper, устанавливает её root:root 0755 в
`/usr/local/libexec/dlp-lab/fanotify-gateway`, создаёт root-owned родитель
`/var/lib/dlp-lab` и каталог `watch` с владельцем roman и режимом 0700.
Правило `/etc/sudoers.d/dlp-lab-fanotify` (root:root 0440) добавляется последним.
При ошибке итоговой проверки visudo новое правило удаляется.
Существующие пути установщик не перезаписывает. После частичного сбоя сначала
проверить созданные файлы; повторная установка сама не удаляет их.

## Что именно разрешается

```sudoers
roman ALL=(root) NOPASSWD: NOSETENV: /usr/local/libexec/dlp-lab/fanotify-gateway ""
```

Пустые кавычки означают отсутствие аргументов, а не любые аргументы.
Сама установленная программа также отвергает любые аргументы, очищает окружение,
использует фиксированные каталог и UID/GID и сбрасывает все три UID/GID и
supplementary groups перед выполнением Python. no_new_privs запрещает последующее
повышение прав в worker. Python читает изменяемый код workspace уже от roman.
Root никогда не запускает Python, shell или программу, указанную вызывающим.

Разрешение относится ко всем процессам пользователя roman, включая команды агента,
а не только к конкретной задаче Codex. Ограничения песочницы Codex остаются в силе:
для запуска gateway агенту может потребоваться отдельное разрешение приложения
на команду за пределами песочницы. Это правило не меняет общий режим Codex.

[Документация sudoers](https://www.sudo.ws/docs/man/1.9.14/sudoers.man.pdf)
описывает ограничения аргументов и теги NOPASSWD/NOSETENV.

## Проверка после установки

Остановить ранее запущенные monitor для этого тестового каталога, затем:

```bash
cd /home/roman/dlp-lab
make privileged-test
```

Harness работает от roman, вызывает только фиксированный gateway через `sudo -n`,
проверяет UID, отсутствие effective capabilities, no_new_privs, ALLOW/WARN/BLOCK
и освобождение наблюдения после выхода. После установки я смогу запускать этот
тест без пароля, с учётом разрешений среды исполнения.

Для длительного эксперимента используется та же команда без аргументов:

```bash
sudo -n /usr/local/libexec/dlp-lab/fanotify-gateway
```

Она наблюдает только непосредственных детей `/var/lib/dlp-lab/watch`.
Прерывание Ctrl+C снимает наблюдение. Журналы не помещать внутрь watch.

## Отзыв доступа

Удалить только добавленное правило (потребуется пароль):

```bash
sudo rm -- /etc/sudoers.d/dlp-lab-fanotify
sudo /usr/sbin/visudo -c
```

Это запретит новые беспарольные запуски; уже запущенный worker нужно отдельно
остановить. Данные watch не удаляются. Для обновления установленного C-helper
снова требуется осознанная административная установка; агент не может заменить
защищённый бинарник через предоставленное правило.

## Выполненные проверки

Обе версии C-helper собраны с предупреждениями как ошибками. Установленная версия
дополнительно использует FORTIFY, stack protector, PIE, RELRO/NOW.
Проверены отказы при лишних аргументах и запуске без root, bash -n для установщика,
visudo -cf для правила (parsed OK), 17 тестов ядра. Два привилегированных теста
пропущены до установки/предоставления доступа. visudo внутри песочницы также
предупреждает об отображении системного владельца как 65534; это не повод менять
владельцев системных файлов. Установку выполнять только из обычного host terminal.

## Обновление до контроля файловых систем — 2026-10-19

Текст выше описывает первоначальный gateway одного каталога. Новый установщик
собирает `native/filesystem_launcher.c`; для существующей установки подготовлен
отдельный `scripts/update-fanotify-access.sh`. Системный бинарник в ходе разработки
не заменён: sudo для установки запрашивает пароль пользователя.

```bash
sudo /usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin /bin/bash /home/roman/dlp-lab/scripts/update-fanotify-access.sh
```

Перед обновлением остановить files. Скрипт сохраняет предыдущий бинарник и
атомарно устанавливает новый; sudoers не расширяется. Теперь native broker
остаётся root и владеет широкой группой fanotify, а Python работает от roman и
получает только выбранные дескрипторы Telegram. Область, исключения, ограничения,
проверка и ручной опыт описаны в [ADR-012](decisions/012-filesystem-scope.md).
Новая установка через install-fanotify-access.sh сразу использует эту архитектуру.

Для отката сначала остановить files, затем в административном терминале:

```bash
sudo install -o root -g root -m 0755 /usr/local/libexec/dlp-lab/fanotify-gateway.previous /usr/local/libexec/dlp-lab/fanotify-gateway
```

После отката область определяется восстановленным бинарником; панель показывает
её только по событию готовности нового запуска. Предыдущий файл сохраняется только
после успешной первой операции обновления.
