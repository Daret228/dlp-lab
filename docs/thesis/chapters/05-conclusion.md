# ЗАКЛЮЧЕНИЕ

Разработан модульный прототип DLP Lab для контроля информации в настольных мессенджерах Linux. Файловые события, выбранные текстовые поля и доступные локальные данные приводятся к общим моделям и анализируются единым ядром. Telegram Desktop и Signal Desktop проверены отдельными стендовыми опытами. Результаты сгруппированы по источнику данных и виду выполненного действия.

Файловый модуль использует fanotify и отдельный привилегированный брокер. На собственном стенде подтверждены разрешение обычных файлов и отказ открытия чувствительных вложений. Область расширена с тестового каталога до локальных файловых систем с явными исключениями. Исключения для профилей, кешей и служебного файла Xauthority обеспечивают совместимость с рабочим окружением. Журнал отдельно фиксирует решение анализатора и ответ на запрос открытия.

Контроль выбранного поля AT-SPI обеспечивает анализ изменений, предупреждение и журналирование. Для Telegram реализовано чтение локальных черновиков и файловых метаданных. Для Signal реализован анализ выборки текстов из копии SQLCipher-базы закрытого тестового клиента со штатным доступом к ключу. JSON-экспорт Telegram сохранён как дополнительный источник.

К словарям, регулярным выражениям и контекстным правилам добавлен обучаемый линейный классификатор финансовых сведений, паспортных данных и данных доступа. На диагностическом наборе из 44 примеров итоговая модель дала 39 полных совпадений и macro F1 0,8957. Показатели характеризуют диагностическую синтетическую выборку, использованную при доработке модели. В основной политике ML выключен; при включении он формирует предупреждение и не отменяет более строгое решение правил.

Реализованы DEB-поставка для Debian 12 и 13, системные службы, ручной запуск, самостоятельный установщик и команда диагностики. Центральный сервер принимает минимизированные события по HTTPS, различает устройства и выдаёт фиксированные задания диагностики, перезапуска и применения политики. Серии открытий сводятся к одной итоговой операции с именем файла и причиной; фильтры журнала отделяют документные события от технических при сохранении полного аудита. Политика типов файлов по сигнатуре настраивается для каждого устройства отдельно, включая раздельное разрешение изображений для разных ролей. На двухмашинном стенде подтверждены доставка событий, получение отчётов, повторное применение установщика, автозапуск после перезагрузки и сквозное применение политики с сервера на обоих устройствах.

Последний автоматический набор версии 0.2.29 содержит 330 тестов, из которых 327 прошли и три пропущены по условиям запуска; набор выполняется на Debian 13 и в сборке пакета Debian 12. Исторические измерения времени характеризуют только ядро анализа TextContent, а не задержку файлового контроля или сетевой доставки. Системные опыты и пользовательские подтверждения приведены отдельно от автоматических тестов.

Практический результат — свободно распространяемый под MIT комплекс с механизмами обнаружения, аудита и предотвращения открытия чувствительных файлов целевыми мессенджерами; собранные пакеты публикуются в выпусках репозитория проекта. Дальнейшая работа включает OCR сканов и изображений с проверкой извлечённого текста, независимый корпус для ML, испытания отказов доставки, установку на чистую ОС вне одноразового окружения и удалённую установку обновлений пакетов.
