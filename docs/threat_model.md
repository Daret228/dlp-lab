# Модель угроз и ограничения прототипа

## Объекты защиты и доверие

Защищаем тестовые конфиденциальные файлы и явно выбранные drafts пользователя endpoint.
Доверяем ядру, администратору, коду helper и конфигурации. Мессенджер — приложение,
запрашивающее доступ к данным, а не достоверный источник сведений об отправке.
Тестируется только собственный UID и согласованные тестовые аккаунты.

Доступ к исходному файлу и к ключам профиля не является разрешением расшифровывать
защищённое хранилище. Нет TLS MITM, keylogging, внедрения кода, патчей клиентов,
эксплуатации уязвимостей или чтения профилей других пользователей.

2026-10-09 пользователь отдельно разрешил offline-чтение собственного тестового
хранилища с локальным ключом в памяти, без подбора и извлечения сетевых ключей.
Реализовано ограниченное чтение черновиков: временная зашифрованная копия 0700/0600,
без записи текста/ключей в аудит, без configs/сетевой авторизации, core dumps
отключены. Python не гарантирует обнуление памяти, SIGKILL может оставить копию;
swap/root и компрометация самого агента не покрываются. Для поиска маркера
расшифровываются черновики выбранного аккаунта в пределах лимита, поэтому
использовать собственный тестовый профиль. См. ADR-007 и протокол local reader.

## Угрозы и меры

| Угроза | Реализовано | Остаток |
|---|---|---|
| Случайная передача чувствительного UTF-8 файла | Контентные правила + permission response в PoC | Kernel test и Telegram проверены; покрытие ограничено каталогом и выбранным executable |
| Подмена пути между событием и анализом | Анализ event fd, fstat до/после | Изменение содержимого после ответа остаётся возможным |
| ReDoS/огромный input | Ограничения размера и времени, on_error | Внешний watchdog нужен против неотменяемого kernel IO и зависания аудита |
| Внедрение через YAML | SafeLoader, строгая схема, уникальные ключи | Администратор отвечает за доверенные файлы политики |
| Утечка через журнал | Только offsets и метаданные, без текста | Пути и executable сами чувствительны; прямые файлы журнала требуют ограниченных прав; общий journal зависит от настроек хоста |
| Отказ worker/очереди | Аудит overflow; закрытие fd | Fail-open после смерти worker; нет полной гарантии доставки аудита |
| Убийство/подмена агента пользователем | Не решено | User systemd управляет процессами, но пользователь может остановить их; защищённая служба и broker — вне PoC |

Уже открытые файлы, mmap, скриншоты, ручное перепечатывание, буфер обмена,
переименование/копирование за scope и альтернативные приложения не покрываются.
PoC наблюдает непосредственных детей одного каталога, не всю систему.
WARN разрешает операцию и не требует подтверждения пользователя.

Оценка результатов ВКР: отдельно измерять качество классификации (precision,
recall на синтетическом корпусе), задержку open и полноту событий. Нельзя заменять
метрику реальных отправок числом open или выдавать непроверенные GUI возможности
за защиту. Отсутствие события не является доказательством отсутствия утечки.
