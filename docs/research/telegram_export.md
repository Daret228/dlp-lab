# Telegram: адаптер явного JSON-экспорта

Дата: 2026-10-06. Реализован, проверен на синтетических данных и двух
реальных тестовых экспортах, предоставленных пользователем.

## Источник и область

Telegram документирует экспорт отдельного чата через его меню и форматы JSON/HTML:
[официальное описание](https://telegram.org/blog/export-and-more).
Структура сверена с [JSON writer на теге v7.2.8](https://github.com/telegramdesktop/tdesktop/blob/v7.2.8/Telegram/SourceFiles/export/output/export_output_json.cpp):
корень одного чата содержит id/type/messages, записи имеют тип message/service,
text — строка либо массив строк и объектов с полем text; date_unixtime — строка
секунд Unix. Этот тег не идентифицирует установленную сборку.

Reader работает только с явно указанным файлом. Не обращается к tdata, Telegram,
сети, ключам, другим чатам или путям вложений. Экспорт готовит пользователь.
Это исторический анализ выбранных данных, а не мониторинг живой базы или send veto.

## Нормализация

| NormalizedMessage | Источник / правило |
|---|---|
| messenger, source | telegram, telegram_json_export |
| chat | строковое представление id корня |
| sender | from_id, при отсутствии — None; имя from не используется |
| account, recipient | None: достоверно определить по отдельному чату нельзя |
| timestamp | date_unixtime → ISO UTC; без него date → ISO, без догадки о часовом поясе |
| text | строка или соединение частей массива без добавления разделителей |
| attachments | строки file/photo, включая возможные отметки о невыгруженных файлах |
| metadata | message_id, record_index (с 1, включая service), timestamp_basis |

Нормализованные объекты содержатся только в памяти. В аудит идут порядковый номер
записи, решение и findings без фрагментов текста. Название чата, sender/chat/message ID,
дата сообщения, пути файлов и текст туда не записываются. Timestamp самого события
аудита — время анализа, не время отправки. Ошибки reader содержат фиксированную
диагностику, без входных значений.

## Границы покрытия

- Поддерживается один чат; полный экспорт аккаунта и HTML отклоняются.
- Анализируется только text обычных message: текст и подписи в этом поле.
  text_entities не дублируется. href, контакты, опросы, вложенные rich-структуры,
  данные пересылки, реакции, служебные действия и содержимое файлов не анализируются.
- service и пустой text считаются отдельно; пустой текст не получает ALLOW.
  Счётчик ссылок на вложения не является полной инвентаризацией медиа.
- `scope=message_text_only`, `attachments_analyzed=false`, `enforcement=none`.
  `text_analysis_complete=true` означает завершённую проверку выбранных непустых
  текстов, а не полноту истории, всех полей, вложений или отсутствие утечки.
- ALLOW/WARN/BLOCK — классификация уже экспортированного текста. Направление
  сообщения и факт утечки не выводятся. Проверяются все обычные сообщения экспорта,
  включая входящие, если они в нём присутствуют.
- Нет утверждения о полноте Telegram-истории: фильтры экспорта, удаление сообщений
  и ограничения самого клиента вне контроля адаптера.

## Ограничения чтения и ошибки

Обычный файл, до 16 MiB и 10 000 записей. Сначала полностью валидируется известная
схема всех message, затем выдаются результаты; некорректная поздняя запись не приводит
к частичному «успешному» отчёту. Неизвестные дополнительные поля допускаются, но
не проверяются анализатором. Неизвестные типы записей/формы text отклоняются.
Дубли ключей JSON и id сообщений запрещены; NaN/Infinity, невалидный UTF-8 и чрезмерная
вложенность JSON отклоняются. UTF-8 BOM допускается.

Открытие O_RDONLY/O_NOFOLLOW/O_NONBLOCK; финальная symlink, FIFO и устройства
не принимаются. Символьные ссылки в родительских каталогах отдельно не запрещены:
это явный путь пользователя, не sandbox для обхода произвольных файлов.
FD закрывается; размер/mtime/ctime сравниваются до и после чтения. Это обнаруживает
обычные изменения во время чтения, но не даёт криптографической аутентичности.
Неизменность atime не гарантируется. JSON разбирается в памяти, streaming нет.
На каждый текст действуют штатные лимиты ContentAnalyzer; общего таймаута пачки нет.

Код выхода 0 — обработка завершена (включая обнаруженный BLOCK), 2 — ошибка чтения,
схемы или неполный анализ; 130 — прерывание. Сводка содержит analysis_failures.

## Как повторить ручной опыт

1. Собственный тестовый чат → ⋮ → «Экспорт истории чата».
2. Выбрать JSON/машиночитаемый формат, отключить медиа, указать небольшой диапазон.
3. Сохранить в `/home/roman/dlp-lab/private-exports/` (права каталога 0700, Git ignore).
4. Передать точный путь к result.json команде `analyze-export --file`.
5. Сверить число записей и решения с тестовыми сообщениями; сохранить только
   обезличенные итоги и сведения о совместимости, не сообщения или сам экспорт.

Не отправлять реальные секреты для проверки. Root и перезапуск Telegram не нужны.
