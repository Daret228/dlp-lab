# Доступ к содержательным данным tdata: проверка 2026-10-09

## Результат

В изученных интерфейсах Telegram Desktop v7.2.8 не найден внешний запрос для
чтения черновиков, locations или search suggestions из локального хранилища.
Это ограниченный вывод по перечисленным исходникам, не доказательство отсутствия
всех возможных интерфейсов во всех версиях. Прямой reader не реализован.
Пользователь подтвердил: доступа к eXpress и тестовому аккаунту нет.

Локальная проверка: /opt/telegram-desktop/Telegram существует, 238112592 байта;
пакет telegram-desktop-local версии 0+local.20260911142732. Эта версия пакета
не удостоверяет upstream-версию бинарника. В /opt и стандартных каталогах
.desktop файлов совпадений с express не найдено, dpkg также не выдал его пакет.
Версия установленного Telegram и соответствие исходникам остаются неизвестными.
Программа повторно не запускалась; профиль и настройки не изменялись.

## Проверенные пути

| Путь | Наблюдение | Значение для проекта |
|---|---|---|
| Storage::Account | readDraftsWithCursors, readFileLocation, downloadsSerialized, readSearchSuggestions — внутренние методы C++ | Их нельзя вызвать из нашего Python как готовый API запущенного клиента |
| Дисковые записи | readLocations/readDraftsWithCursors/readSearchSuggestions используют ReadEncryptedFile и _localKey | Нельзя заменить разбором открытого JSON/SQLite; ключи не извлекались |
| Командная строка | processArguments содержит запуск, workdir, настройки и URL; команды выгрузки нужных структур не обнаружены | Запуск с вымышленным --dump-db не является решением |
| Локальный IPC | readClients разбирает CMD, OPEN и CTRL; CTRL передаётся HandleExternalControl | Наличие сокета само по себе не означает доступ к хранилищу |
| CTRL | Перечислены ping, окна/активация, блокировка, прокси, темы, отключение автоматизации | В обработчике нет чтения целевых структур; настройки автоматизации не включались |
| TDLib | Отдельная библиотека клиента со своим локальным хранением | Не является адаптером к существующему tdata Telegram Desktop |

Особенность: внутренние методы чтения могут очищать повреждённые записи и
изменять карту при ошибке. Их нельзя просто запускать на исходном профиле и
объявлять операцию read-only.

## Конкретный вариант для согласования — отдельная тестовая сборка

Статус: предложение, не согласовано и не реализовано. Этот вариант требует
изменения клиента; правило проекта запрещает считать такое предложение решением.

Цель минимального опыта: доказать чтение одного искусственного черновика после
перезапуска из локального дискового хранилища, затем передать нормализованные
данные нашему анализатору. Полная история сообщений этим не доказывается.

Предлагаемая последовательность:
1. Отдельная сборка и отдельный тестовый профиль, не замена рабочего Telegram.
   Зафиксировать версию исходников и зависимости, отдельно оценить возможность сборки.
2. В штатный путь успешного чтения локального черновика добавить ограниченный
   диагностический адаптер. Клиент сам выполняет своё обычное чтение; ключи и
   сессии не передаются агенту. Не использовать внедрение в работающий процесс.
3. Выбор ровно одного тестового чата внутри клиента. Данные только после
   успешного чтения дисковой записи; события изменения GUI иметь другой source.
4. Локальный канал к агенту с проверкой владельца/прав, ограничением размера,
   схемой версии, запретом доступа при заблокированном клиенте и явным статусом
   ошибки. Решения хранить без исходного текста. Канал не открывать в сеть.
5. Приёмка: создать искусственный черновик, завершить клиент; отключить сетевое
   подключение тестового экземпляра; открыть тестовый профиль и подтвердить,
   что событие получено из успешного дискового чтения. Профиль должен быть
   доступен штатному клиенту; отсутствие сети и источник записи нужно доказать.
6. Сопоставить текст и форматирование с заранее известной синтетикой, проверить
   ALLOW/WARN/BLOCK, ошибки, блокировку профиля, перезапуск и отсутствие ключей
   в канале. Только после этого исследовать метаданные вложений.

Это интеграция агента с согласованной сборкой. Если ВКР требует именно независимого
агента для неизменённого клиента, такой вариант может не подойти. Его необходимо
согласовать с руководителем. Даже при реализации нельзя обещать полную историю
или универсальность для других мессенджеров.

## Альтернативы и следующий выбор

- Получить собственную тестовую среду другого мессенджера и проверить реальную
  локальную базу. Пока доступа к eXpress нет, нельзя заявлять его поддержку.
- Прямое чтение защищённого tdata отдельным инструментом потребовало бы отдельно
  согласованной работы с локальными ключами/расшифровкой; текущие рамки это
  исключают. Техническую невозможность вообще не утверждаем.
- JSON и stat оставить дополнительными каналами, не подменять ими требование БД.

Дальнейшее повторение stat-опытов уточняет косвенные признаки, но не устраняет
ограничение доступа к полям. До выбора способа интеграции развитие прямого reader
не имеет подтверждённой основы. Уведомления и аудит текстового монитора можно
дорабатывать независимо. Код агента на этом этапе не менялся, тесты не запускались.

## Последующее решение и результат

Пользователь отклонил изменение Telegram, затем явно разрешил внешний reader
зашифрованной копии собственного тестового хранилища с локальным ключом в памяти,
без подбора и извлечения сетевых ключей. Ограниченное чтение черновика реализовано
и проверено в тот же день: [протокол](telegram_local_reader_2026-10-09.md).
Отсутствие внешнего IPC-метода не означает невозможность такого offline-чтения.
