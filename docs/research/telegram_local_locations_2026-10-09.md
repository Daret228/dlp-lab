# Локальные сведения о файлах Telegram — 2026-10-09

## Статус

Реализован ограниченный offline-reader записей file locations; проверен на
синтетических зашифрованных контейнерах и на собственном реальном тестовом профиле
2026-10-09: найдена одна запись исходного искусственного файла (подробности ниже).
Это косвенные признаки работы с локальными файлами, не история отправок.

## Основание формата

Проверены публичные исходники Telegram Desktop v7.2.9:
- [storage_account.cpp](https://github.com/telegramdesktop/tdesktop/blob/v7.2.9/Telegram/SourceFiles/storage/storage_account.cpp):
  секция карты lskLocations=4, writeLocations/readLocations;
- [file_location.cpp](https://github.com/telegramdesktop/tdesktop/blob/v7.2.9/Telegram/SourceFiles/core/file_location.cpp):
  modified=QFileInfo.lastModified(), size=QFileInfo.size();
- [data_document.cpp](https://github.com/telegramdesktop/tdesktop/blob/v7.2.9/Telegram/SourceFiles/data/data_document.cpp):
  сведения используются при сохранении файлов и работе с медиакешем;
- [storage_file_utilities.cpp](https://github.com/telegramdesktop/tdesktop/blob/v7.2.9/Telegram/SourceFiles/storage/storage_file_utilities.cpp):
  QDataStream::Qt_5_1;
- [Qt qdatetime.cpp](https://github.com/qt/qtbase/blob/v6.8.3/src/corelib/time/qdatetime.cpp):
  Julian day int64, milliseconds uint32, private Spec int8 для Qt_5_1.

Запись: два uint64 медиассылки, legacy uint32, QString пути, QByteArray bookmark,
QDateTime изменения файла, uint32 размера. Список завершается нулевой записью;
далее aliases и опциональные legacy web locations / blob downloads.
Время не является временем отправки; неизвестный часовой пояс не подменяется UTC.
Идентификаторы медиассылок не являются сетевыми ключами авторизации и не выводятся.

## Реализация и границы

`src/dlp/telegram_locations.py`, `scripts/inspect-telegram-local-locations.py`.
Читаются только key_datas, maps и один файл locations; configs, сетевые ключи
авторизации, черновики и содержимое файлов-вложений не открываются. Чтение карты
использует общий строгий parser; его ограничение в 32 ссылки черновиков сохраняется.
Сначала определяется подмножество файлов, затем создаётся зашифрованная временная
копия и проверяется повторным чтением. Это не атомарный snapshot, Telegram должен
быть полностью закрыт. --profile-closed — подтверждение оператора, не проверка процесса.

В памяти разбираются и посторонние записи locations для проверки формата, но
выводятся только агрегаты и размер/mtime/bookmark_present для точного указанного
абсолютного пути с именем DLP_STORAGE_ATTACHMENT_TEST.txt. Сам путь, медиассылки,
bookmark и содержимое downloads не выводятся. Ноль совпадений — отсутствие записи
в доступном разделе, а не доказательство отсутствия отправки. Несколько совпадений
показываются явно, не выдаются за уникальную запись. Решения ALLOW/WARN/BLOCK здесь
нет: содержимое не анализируется. send_confirmed=false, enforcement=none.

Лимиты: версии контейнера 7002008/7002009, файл 4 MiB, до 10 000 записей/aliases,
30 секунд. Неподдерживаемая/повреждённая структура — код 2, complete=false. Копия
0700/0600 удаляется при штатном выходе; SIGKILL может оставить её. Защита от swap,
root и гарантированное обнуление Python-памяти не обеспечиваются (как у draft reader).

## Ручной опыт

1. В своём тестовом чате отправить искусственный файл
   /home/roman/dlp-lab/examples/DLP_STORAGE_ATTACHMENT_TEST.txt вручную.
2. В Telegram выполнить «Сохранить как» для него в
   /home/roman/dlp-lab/build/DLP_STORAGE_ATTACHMENT_TEST.txt.
3. Полностью завершить Telegram через «Выход».
4. Проверить отсутствие процесса Telegram и выполнить:

```sh
cd /home/roman/dlp-lab
PYTHONPATH=src:.deps python3 scripts/inspect-telegram-local-locations.py \
  --root /home/roman/.local/share/TelegramDesktop/tdata \
  --profile-closed --no-passcode \
  --expected-path /home/roman/dlp-lab/build/DLP_STORAGE_ATTACHMENT_TEST.txt
```

Сопоставить размер и mtime только этого искусственного файла с записью. Возможен
нулевой результат: тогда исследовать штатное сохранение, не объявлять успех.
Даже совпадение не доказывает отправку: опыт прежде всего проверяет сведения о
сохранённом локальном файле. Исходный профиль не менять.
