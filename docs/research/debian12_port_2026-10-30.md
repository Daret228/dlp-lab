# Перенос сборки на Debian 12

Цель: нативный DEB для amd64/Python3.11/glibc2.36 без замены libc и подключения
репозиториев Debian13 на целевой VM. Исходная платформа проекта Debian13.

Найденные проблемы:
- готовые бинарники gateway и SQLCipher с Debian13 требуют libc>=2.38;
- bookworm предлагает SQLCipher3, а reader Signal требует SQLCipher4;
- Telegram reader импортировал только Crypto, пакет Debian использует Cryptodome;
- два теста были привязаны к /usr/bin/python3.13 и один к /home/roman;
- заглушка os.readlink также затрагивала разрешение пути executable на Python3.11.

Решение: Telegram reader поддерживает Cryptodome и Crypto. Тесты используют
sys.executable/домашний каталог среды; PermissionError имитируется только для
/proc, при этом поддельный процесс возвращает реальный объект пути exe.

SQLCipher: Debian source 4.6.1-2 получен apt-get source через отдельный список
источников и подписанный индекс trixie на исходной машине. Системные sources.list
обеих машин не менялись. Патчи Debian применены dpkg-source. Исходники переданы
на Debian12, scripts/build-sqlcipher-bookworm.sh собирает только runtime DEB
libsqlcipher1 4.6.1-2~dlplab12.1. Зависимости вычисляет dpkg-shlibdeps на Debian12.
libsqlcipher0/SQLite системы не заменяются; используется другой SONAME.
Это локальная пересборка, не официальный backport и не заявление о полном аудите
upstream. Обновления безопасности этой локальной зависимости требуют сопровождения.

DLP собирается dpkg-buildpackage с полными тестами, версия 0.2.9~deb12u1. Скрипт
SQLCipher повторяемый, но бинарная воспроизводимость не заявлена. Криптографические
проверки DLP используют только синтетическую базу, ключи и данные не из профиля.
Результаты сборки/испытаний фиксируются в PROJECT_CONTEXT.md после завершения.
