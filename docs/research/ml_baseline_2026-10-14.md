# Первый локальный ML baseline — 2026-10-14

Статус: обучен и проверен offline; к агенту и блокировкам не подключён.

## Метод и воспроизведение

Реализован Multinomial Naive Bayes для каждой из трёх категорий отдельно
(one-vs-rest), сглаживание alpha=1, эмпирические априорные частоты. Стандартная
библиотека Python, без загрузки моделей и без новых внешних зависимостей.
Формулы: [документация Multinomial NB](https://scikit-learn.org/stable/modules/naive_bayes.html#multinomial-naive-bayes).
Используется собственная небольшая реализация, не библиотека sklearn.

Признаки: NFKC/casefold, цифры заменяются нулями, частоты слов и внутрисловных
символьных 3/4/5-грамм с границами. Словарь строится только на train. Служебные
поля датасета не используются как признаки. Пустой массив предсказаний не является
гарантией безопасности; нет решения ALLOW/BLOCK. Отдельные категории могут сочетаться.

Пороги log-odds выбирались на dev из заранее заданной сетки -10,-5,0,5,10:
максимум F2, затем меньше ложных срабатываний, затем более строгий порог.
Эти оценки не являются откалиброванными вероятностями. После просмотра test
параметры не менялись. На реальных рабочих данных подход не проверен.

```sh
PYTHONPATH=src:.deps python3 scripts/train-ml-baseline.py
printf '%s' 'Встречаемся завтра' | PYTHONPATH=src:.deps python3 scripts/predict-ml-baseline.py
```

Модель: build/ml/baseline-v1/model.json; результаты: соседний metrics.json.
Оба файла локальные, build исключён из Git. JSON не исполняет pickle-код.
Модель содержит обученный словарь: при переходе на реальные данные сам артефакт
может содержать части секретов, его нельзя считать обезличенным. Сейчас только синтетика.
Ввод offline-команды ограничен 16 КиБ, превышение — ошибка, не усечение.
Команда предсказания читает stdin и выводит категории без исходного текста.
Поддержка длинных документов и интеграция с извлечением пока не реализованы для ML.

## Зафиксированный результат

Набор v2: 104 train / 26 dev / 26 test. На test 20 чувствительных и 6 обычных
текстов; 2 чувствительных имеют смешанные метки. Метки предварительные.

| Категория | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| financial | 6 | 2 | 1 | 0.750 | 0.857 | 0.800 |
| passport | 6 | 2 | 2 | 0.750 | 0.750 | 0.750 |
| credentials | 6 | 4 | 1 | 0.600 | 0.857 | 0.706 |

Критическая проблема: **все 6 обычных текстов дали ложную тревогу**.
На dev тоже 6 из 6. На test хотя бы одна категория предсказана для всех 20
чувствительных текстов, но это бесполезно без специфичности: модель помечает
вообще все тестовые сообщения. Точное совпадение набора категорий — 16 из 26.
Не представлять 100% обнаружения как успех или готовность к эксплуатации.

По ошибкам видна зависимость от темы/лексики, а не надёжное различение передачи
значения и обсуждения темы. Это гипотеза по наблюдаемым ошибкам, не исследование
интерпретируемости. Есть путаница категорий на английских текстах и пропуски
одной из меток в смешанных сообщениях. Подробные ID ошибок сохранены в metrics.json.

Существующая политика правил на этом же наборе не нашла ни один из 20
чувствительных текстов: её текущие правила относятся к секретным фразам, email
и контексту проекта. Это отсутствие покрытия новых категорий, а не доказательство
превосходства ML над специально настроенными правилами паспортов/финансов/секретов.

Следующий шаг: доработать признаки передачи конкретных реквизитов, добавить
контрастные пары «упоминание темы / реальные значения», выделить независимый
контрольный набор, сравнить с новыми специализированными правилами. Не включать
этот baseline в автоматическую блокировку. Не подбирать параметры по текущему test.

## Проверка реализации

Шесть новых тестов: расчёт по формуле сглаженного likelihood, ограничения train/dev,
неизменность модели при оценке, метрики с известными TP/FP/FN/TN, JSON roundtrip,
несколько меток/пустой ввод, нормализация/лимит, пороги не меняют веса.
Полный запуск make test: 117 тестов, 115 прошли, 2 opt-in пропущены.
Структура обоих наборов проверена валидатором, точных нормализованных дублей и
пересечений групп не найдено. Это не доказательство семантической независимости.
