# Контроль значений и ML: эксперименты v3/v4 — 2026-10-14

## Критерий и методика

Пользователь попросил продолжать до хорошего результата. Перед доработкой объявлен
критерий: обнаружение ≥90%, ложные тревоги ≤5% на отложенной проверке. Для оценки
дополнительно потребованы precision и recall ≥90% для каждой категории.
Критерий относится к наблюдаемой доле на небольшом синтетическом наборе,
не к гарантированной вероятности ошибки на реальных документах.

Сохранён неудачный baseline-v1. Добавлены 18 контрастных пар (36 вымышленных
текстов) к 104 train; переобучен тот же NB на 140 текстах. Пороги выбраны только
по прежнему dev из 26 текстов; test-v2 не использовался как независимая проверка.
Модель хранится в build/ml/hybrid-v3/model.json. Для v4 её веса и пороги не менялись.

В v3 добавлены явные признаки передачи значения: паспортные группы цифр,
карта/счёт, финансовый контекст с суммой, секрет доступа со значением. В гибриде
уверенный структурный признак достаточен, ML допускается лишь для ограниченных
финансовых кандидатов с суммой и контекстом. Одно ключевое слово без значения
не должно становиться положительным результатом только из-за ML.

В v4 усилено связывание значения с полем: обработка масок и отсутствующих
значений, границы предложений/полей, отдельные поля телефона/заказа, явные
короткие/русские пароли и кодовые фразы. V3 сохранён в отдельном неизменённом
модуле для воспроизводимости. Изменения v4 проверялись на unit/development cases,
затем создан и один раз оценён дополнительный набор. После оценки v4 код
классификатора и пороги не менялись под найденные ошибки.

финансовый случай к правилам v3, но этого недостаточно для доказательства
обобщающей пользы модели. Нельзя выдавать улучшение правил за улучшение ML.
Следующая ML-итерация должна показать пользу по сравнению с этими правилами
на новом независимом наборе; до этого не делать ML решающим для блокировки.

## Ограничения оценки

Автор кода и текстов один. Отсутствие использования test при обучении не делает
оценку внешне независимой. Проверено отсутствие точных нормализованных дублей и
пересечения group_id между обучением/dev и новыми holdout; это не исключает
сходства формулировок и источников. Некоторые формы в holdout родственны
обучающим. Синтетические цифровые шаблоны и пароли не репрезентативны для всех данных.

0/12 ложных тревог — лишь наблюдение: верхняя граница двустороннего 95% интервала
Уилсона около 24%, поэтому статистически доказать уровень ≤5% этим набором нельзя.
Не заявлять промышленную готовность или универсальность. Реальные рабочие данные,
обфускация, OCR, многоязычие, длинные документы и распределения организаций
полноценно не проверены. Существование номера документа или работоспособность
пароля не проверяются. Опубликованность финансовых данных определяется эвристически.

После просмотра каждый holdout считается раскрытым. Дальнейшая настройка по его
ошибкам допустима только с последующей новой контрольной проверкой.

## Использование без автоматической блокировки

```sh
cd /home/roman/dlp-lab
printf '%s' 'Пароль: сиреневыйлес' | PYTHONPATH=src:.deps python3 scripts/predict-sensitive.py --stdin
printf '%s' 'Нужно сменить пароль' | PYTHONPATH=src:.deps python3 scripts/predict-sensitive.py --stdin
PYTHONPATH=src:.deps python3 scripts/predict-sensitive.py --file /путь/к/документу.docx
```

Первый пример: credentials, второй: пустой labels. Результаты содержат scope,
complete и enforcement=none; исходный текст не печатается. Для сравнения
есть --mode rules и --mode ml. Пустой labels не означает универсальную безопасность.
Политические решения ALLOW/WARN/BLOCK остаются отдельной задачей интеграции.

TXT UTF-8, PDF и DOCX используют имеющееся ограниченное извлечение. Лимит
ML-текста 16 КиБ; больший текст вызывает ошибку, не усечение и не «безопасно».
Для документов действуют размер входа/политика форматов, сроки и ограничения
существующего extractor. Неполное извлечение сохраняет complete=false; классификация
извлечённой части не делает весь документ проверенным. OCR отсутствует.
CLI не является агентом и ничего не запрещает в Telegram.

В обычной среде модель уже существует. В чистой копии после установки обычных
зависимостей проекта сначала выполнить:

```sh
PYTHONPATH=src:.deps python3 scripts/evaluate-ml-hybrid.py fit
```

Повторное обучение поверх существующей модели скрипт отклоняет. Новые эксперименты
должны получать новые версии, а не стирать доказательства предыдущего результата.
Для воспроизведения holdout-v3: evaluate-ml-hybrid.py holdout. Для v4:
evaluate-ml-hybrid-v4.py. Оба откажут при уже существующем отчёте; читать сохранённый.
Манифесты фиксируют входы/модель/код SHA256 до оценки. Версионируемые копии отчётов:
data/ml/experiment-reports/. Файлы модели содержат словарь и не должны считаться
обезличенными при будущем обучении на настоящих данных.
