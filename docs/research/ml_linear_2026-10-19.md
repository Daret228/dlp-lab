# Обучаемый ML-классификатор — 2026-10-19

Исторический отчёт первоначальной интеграции. Текущий артефакт заменён:

## Реализация

Локальная one-vs-rest логистическая регрессия для financial, passport и credentials.
Модель обучается по размеченным примерам независимо от словарных правил.
Признаки: слова, пары слов, символьные n-граммы 3–5 и общие признаки формы.
Используются обученный на train IDF и L2-нормализация; реализация на Python stdlib.
Веса слов/пар/символьных признаков в последнем варианте: 3/5/0.35.
Регуляризация выбирается по dev из 0.001/0.01/0.1, 250 эпох;
пороги классов подбираются на dev. Test не используется внутри fit/calibrate.
Значение sigmoid не является калиброванной вероятностью утечки.

Модель подключена к ContentAnalyzer, следовательно к анализу текста,
извлечённого содержимого документов и черновиков через существующие адаптеры.
Результат имеет analyzer=ml и отдельные метаданные. ML повышает ALLOW до WARN,
не снимает BLOCK правил и сам не блокирует отправку. Повреждение модели,
таймаут или превышение лимита дают неполный анализ, а не молчаливый ALLOW.
JSON-модель проверяется по SHA256 и структуре; pickle не применяется.
Панель позволяет включать ML отдельно от правил; модули требуют перезапуска.

## Данные и ограничения эксперимента

linear-v1: train 346, dev 26, test 60. Ранее раскрытые holdout включены в train.
linear-v2: train 468, dev 66, новый test 60 (36 чувствительных, 24 обычных).
Данные синтетические, составлены тем же автором; независимой внешней оценки нет.
В train v2 перенесён раскрытый test v1 и добавлены 62 контрастных примера.
Проверяются точные нормализованные дубли, ID и разделение group_id между частями.
Это не гарантирует отсутствие смыслового сходства между примерами.

После просмотра результатов v2 изменялись пороги и признаки. Поэтому test v2
для итоговой модели считается раскрытым: результаты являются диагностическими,
а не независимым доказательством качества. Требуется новая закрытая выборка.

| Опыт | Macro F1 ML | Полностью верных / 60 | Ложные тревоги на обычных / 24 |
|---|---:|---:|---:|
| linear-v1 | 0.8473 | 48 | 8 |
| linear-v2 | 0.9009 | 52 | 7 |
| linear-v3, приоритет precision | 0.6087 | см. metrics.json | 1 |
| linear-v4, веса признаков | 0.9122 | 53 | 6 |

v3 отклонён: ни одного из 12 паспортных примеров не обнаружено.
Итог v4: financial TP=12 FP=4 FN=0; passport TP=12 FP=2 FN=0;
credentials TP=11 FP=0 FN=1. На том же наборе правила дают macro F1=0.8922,
53/60 полностью верных и 2/24 ложных тревог. Преимущество ML в целом не доказано:
большая полнота сопровождается большим числом ложных тревог (25% обычных текстов).
Поэтому в основной политике ML пока выключен, в ml-demo.yaml включён только ML.

## Воспроизведение

Из корня проекта (выберите ещё не существующий каталог результата):

```sh
PYTHONPATH=src:.deps python3 scripts/train-ml-linear.py --data data/ml/linear-v2 --output build/ml/reproduce-new --disclosed-test
./scripts/dlp --policy config/ml-demo.yaml analyze --text 'Пароль: Reka!6831'
```

Команда обучения сохраняет manifest с хешами данных/кода, model и metrics;
не перезаписывает существующий опыт. Артефакт замораживается до оценки test.
Повторный запуск v4 дал побайтово идентичную модель.
Поставляемый артефакт: src/dlp/ml_assets/sensitive-linear-v1.json (имя версии
формата поставки, содержимое из опыта linear-v4), SHA256:
`d0613e39a9c049c9e127548e169af2cfe976f5e472563097c061c596b745b0dc`.
Манифесты и метрики четырёх опытов: data/ml/experiment-reports/linear-v*/.

## Проверено и следующий шаг

180 тестов: 178 успешно, 2 пропущены. Включены 11 ML-тестов: обучение,
валидация модели, отказ без молчаливого ALLOW, независимость от правил,
DOCX, DraftMonitor с уведомлением, редактированный журнал и сохранение политики.
CLI на синтетических тексте и DOCX подтвердил WARN для credentials и ALLOW
для обычного содержимого. Новый ручной опыт в живом Telegram не проводился.

Лимит ML: 16 КиБ UTF-8 текста целиком; OCR отсутствует. Длинные документы
не объявляются полностью проверенными. Отдельная сквозная проверка ML с PDF
в этом этапе не проводилась. Выборки не подтверждают качество на реальных данных.
Следующий шаг: независимая разметка, согласование классов и допустимой частоты
ложных тревог, новая закрытая выборка; улучшение модели оценивать только на ней
после фиксации параметров. ВКР в этом этапе не пересобиралась.
