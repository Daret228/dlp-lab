# Локальное хранилище: уточнённое исследование 2026-10-09

## Требование и результат этапа

Руководитель требует локальную базу, включая косвенные признаки. JSON остаётся
дополнительным источником. На этом этапе прямой reader не реализован: создан
инструмент для проверки гипотез о файловых метаданных, а не замена чтению базы.

Повторная инвентаризация: 502 обычных файла, 236 каталогов, 57 648 592 логических
байта, 737 записей. Прочитаны только три разрешённых восьмибайтовых заголовка
settingss/maps/configs (TDF$, writer 7002008); содержимое остальных файлов не
открывалось. Два файла имеют расширение JSON, расширений SQLite не обнаружено.
Сигнатуры всех файлов не проверялись. Соответствие установленного бинарника
исходникам v7.2.8 по-прежнему не удостоверено.
Отчёт: [telegram_inventory_2026-10-09.json](telegram_inventory_2026-10-09.json).
Рост относительно 6 октября не является свидетельством утечки или отправки.

## Кандидаты для косвенных признаков

Повторно изучен фиксированный [storage_account.cpp v7.2.8](https://raw.githubusercontent.com/telegramdesktop/tdesktop/v7.2.8/Telegram/SourceFiles/storage/storage_account.cpp).

| Структура в исходниках | Возможная польза, пока гипотеза | Доступность нашему агенту |
|---|---|---|
| writeLocations: имена, даты, размеры файлов, сериализованные загрузки | Контекст работы с вложениями | Пишется через writeEncrypted; поля не извлечены |
| writeDrafts: текст, форматирование, контекст ответа | Данные ещё не отправленного сообщения | Прямого reader нет; AT-SPI является отдельным источником |
| writeSearchSuggestions: top/recent peers и другие подсказки | Контекст недавних обращений; не подтверждение переписки | Структура исследована по коду, из профиля не извлечена |
| cache/media_cache | Изменение объёма локальных данных | Доступна статистика файлов, смысл содержимого не установлен |

Это не доказательство присутствия всех структур в данном профиле или полноты
истории. Контакты, ключи, сессии и содержимое сообщений не читались. Полезность
признака требует сравнения с фоновыми изменениями и другими действиями.

## Новый инструмент

`scripts/observe-telegram-storage.py` повторяет ограниченный обход tdata:
stat без чтения содержимого, 10 000 записей, глубина 5, длительность 1–600 секунд,
интервал 0,5–10 секунд. Использует защиту от симлинков и проверки владельца
существующего inventory. Требует Linux, запускается без root.

Относительные имена и stat-данные хранятся только в памяти для сравнения.
В JSONL выводятся агрегаты appeared/disappeared/changed/identity_changed,
изменение логического размера по ограниченным категориям имён и статус полноты.
Категория по имени не удостоверяет тип содержимого. Неполный обход разрывает
сравнение; следующий полный обход становится новой исходной точкой. Ошибка
даёт код 2, Ctrl+C — 130. Изменения не получают решений ALLOW/WARN/BLOCK.

Ограничения: обход не атомарный; короткоживущие файлы и изменения между опросами
могут быть пропущены; переименование выглядит как исчезновение и появление;
изменение timestamp не доказывает изменения текста или отправки. Фоновая работа
Telegram может давать те же признаки. Длительность ограничивает цикл, но не
гарантирует жёсткий таймаут отдельной файловой операции. Это исследовательский
скрипт, не служба агента и не реализованный reader локальной базы.

## Следующий ручной опыт: фон и черновик

1. Открыть собственный тестовый чат Telegram. Запустить из корня проекта:

   ```bash
   python3 scripts/observe-telegram-storage.py --seconds 60 > build/storage-idle.jsonl
   ```

   Минуту не взаимодействовать с Telegram. Это контроль фоновых изменений.
2. Запустить:

   ```bash
   python3 scripts/observe-telegram-storage.py --seconds 60 > build/storage-draft.jsonl
   ```

   Через примерно 10 секунд ввести новый искусственный черновик
   `DLP_STORAGE_TEST пример 123`, не отправлять, оставить до конца минуты.
   Записать фактическое время действия отдельно, не содержимое других черновиков.
3. Сравнить два протокола; повторить минимум три раза с учётом уже существующего
   черновика и отложенных записей. По одному совпадению причинность не утверждать.
   Удаление тестового черновика проводить вне измерения фона или как отдельный опыт.
4. Следующие отдельные опыты: выбор/отмена вложения и просмотр имеющегося
   тестового вложения. Отправку не выполнять автоматически. Для сравнения с
   экспортом достаточно уже предоставленных схем, новый полный экспорт не нужен.

## Нерешённая часть требования

Метаданные файлов сами по себе не закрывают требование руководителя о локальной
базе. Если требуется семантическое чтение защищённых структур Telegram, нужно
согласовать поддерживаемый способ доступа/интеграции либо исследовать локальную
базу другого целевого клиента (eXpress требует тестовой среды). Изменение клиента
и извлечение ключей в текущие согласованные работы не входят. Анализ JSON не
выдавать за решение этой проблемы. DOCX пока отражает предыдущий этап.
