# Локальная проверка через агент и уведомления — 2026-10-09

## Реализовано

`scripts/dlp agent local --profile-closed --no-passcode` запускает разовый
user systemd unit dlp-lab-local.service и ждёт завершения. Не daemon и не live-сбор.
По умолчанию проверяет единственный черновик с DLP_STORAGE_TEST в собственном
~/.local/share/TelegramDesktop/tdata. --root выбирает другой собственный тестовый
профиль; --expected-path дополнительно включает file locations. Код-пароль в
фоновом unit не поддержан: обязателен явный --no-passcode. Пароли не передаются.

Журнал: local_check_started, результаты отдельных проверок, notification_delivery,
local_check_finished с общим run_id. Есть русские пояснения; исходный текст,
ключи и пути профиля не включаются в структурированные события. Systemd хранит
аргументы запуска (пути и тестовый маркер), поэтому это не канал для секретов.
Отсутствие единственного отмеченного черновика — неполная проверка, код 2;
не мешает отдельной проверке locations. Ошибка уведомления также даёт код 2,
хотя complete анализа хранилища может быть true: смотреть notification_status.

До чтения, между задачами и после проверяются имена процессов текущего UID через
/proc. Если comm или доступный exe содержит telegram, чтение не начинается.
Недоступный comm — ошибка; недоступный exe при читаемом comm допускается (на хосте
есть такие посторонние процессы). Это не аттестация бинарника и не блокировка
запуска приложения. Клиент обязан оставаться закрытым: проверки не устраняют гонку
и не делают копирование транзакционным. Все границы прежних offline readers сохранены.

Уведомления общие для AT-SPI-монитора и локального черновика: WARN/BLOCK вызывает
предупреждение без содержимого текста. Сначала notify-send, при его отсутствии
штатный gdbus → org.freedesktop.Notifications.Notify. Таймаут 5 секунд. В журнале
статусы accepted/unavailable/failed/timeout. accepted означает принятие службой,
а не доказательство показа; display_confirmed всегда false. Уведомления адресованы
локальному пользователю, отдельная доставка администратору не реализована.

`agent notification-test` — отдельный разовый unit: искусственная секретная фраза
проходит анализатор, анализ маркирован synthetic=true, затем уведомление и журнал.
Уведомления не отправляют сообщений в Telegram. Запрет отправки не реализован.

## Проверено на хосте

- Первоначальный тест выявил отсутствие notify-send. Прежний монитор в таком
  случае молча пропускал предупреждение. Теперь ошибка видна, добавлен gdbus.
- После исправления notification-test unit завершился success (07:32 UTC).
  В журнале BLOCK/0.8 и notification_delivery/accepted.
  Пользователь подтвердил: «Да, вижу предупреждение». Это подтверждение относится
  к данному искусственному опыту, не ко всем будущим уведомлениям.
- Реальный закрытый профиль, 07:33:17 UTC: единственный отмеченный черновик не найден;
  locations завершился успешно, один исходный тестовый файл, 128 байт. Сводка
  complete=false, failed_checks=1, unit failed — корректный неполный результат.
- Искусственный профиль build/local-agent-synthetic, 07:33:40 UTC: полный путь
  local unit → зашифрованная копия → draft analysis BLOCK/0.8 → notification accepted
  → журнал → finished complete=true, код 0. Это синтетический опыт, не новый
  реальный черновик пользователя. Искусственный профиль оставлен для повторения.
- make test: 88 тестов, 86 прошли, 2 opt-in с привилегиями пропущены. Покрыты запуск
  нового unit, реальный subprocess reader на искусственном профиле, отказ при
  работающем Telegram, результаты доставки/таймаут/D-Bus fallback и отсутствие
  утверждения о показе. Существующие проверки AT-SPI сохранены.

Следующий ручной опыт при необходимости: сохранить секретный отмеченный черновик,
закрыть Telegram и повторить agent local для реального профиля. Отдельно остаётся
повторная сквозная проверка AT-SPI с живым полем после смены backend уведомлений.
Промышленная полнота/защита журнала от пользователя, полный архив сообщений,
live tdata и централизованные уведомления этим изменением не реализованы.
