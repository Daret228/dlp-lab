# Центральный сервер: устройство и возможности

Установка описана в [Docker](DOCKER.md), подключение агента — в
[эксплуатации](OPERATIONS.md). Сервер работает в Docker; агент — в systemd.

Агент анализирует данные локально. Отправщик читает события из системного журнала,
сохраняет очередь и передаёт минимизированную проекцию по HTTPS с индивидуальным
токеном. Сервер хранит события в SQLite и устраняет повторную доставку одного ID.
Токен администратора используется только для административного API/панели.

Панель показывает устройства, события и результаты фиксированных диагностических
заданий и перезапуска файлового/текстового контроля. Root-сервис на агенте
исполняет только эти фиксированные действия; повторы исключаются по ID задания.
С0.2.26 доступно назначение и применение YAML-политики отдельному устройству;
см. [административное управление](ADMIN_CONTROL.md). Удалённая установка пакетов
и произвольный shell через панель не реализованы.

Начиная с0.2.24 агент передаёт `file_operation`: один итог серии открытий
одной версии файла тем же мессенджером и пользователем. Пауза между открытиями
менее5с сохраняет серию, максимальная длительность серии30с. Отправщик сохраняет
незавершённый итог в SQLite и после6с без новых прочитанных событий ставит его
в очередь. Из-за15-секундного опроса результат обычно появляется через15–30с
после завершения серии; недоступность сервера увеличивает задержку.

Итоговый статус: BLOCK выше WARN, WARN выше ALLOW. Применение запрета хранится
отдельно: DENY, если хотя бы одно открытие было запрещено. Содержимое каждого
открытия проверяется независимо; объединяется только отчёт. Подробные события
остаются в системном журнале агента. В панели — одна итоговая строка без списка
промежуточных решений. Повторная доставка не создаёт строку; позднее продолжение
обновляет тот же ID, старый повтор не уменьшает число открытий.

Границы серии — эвристика, не доказательство отдельного нажатия «Отправить».
Разные файлы, версии файлов и мессенджеры не объединяются. Старая история
не переписывается: панель объединяет записи с одним идентификатором группы
независимо от промежуточного решения, с приоритетом BLOCK > WARN > ALLOW. Выборка панели
содержит до200 серверных записей.

Основные файлы: `src/dlp/central.py` (приём, очередь, хранение),
`src/dlp/central_ui.js` и `central_page.html` (панель),
`src/dlp/remote_control.py` (фиксированные задания),
`docker/entrypoint.py` (запуск контейнера).

Недоступность сервера не выключает локальную файловую защиту. Успешный запуск
отправщика ещё не подтверждает доставку: проверьте новое событие в панели.
Резервная копия сервера содержит секреты; см. [обслуживание](MAINTENANCE.md).

В0.2.25 файловые события передают путь (до4096 символов, без управляющих
символов), идентификаторы правил и анализаторов, коды причин проверки.
Это позволяет отличать, например, гипотезу ML от неполной проверки.
Содержимое и совпавшие фрагменты не передаются. Имя видно в строке; полный
путь и правила — в «Подробнее». Поиск поддерживает путь и причину.
Пути могут содержать персональные имена — доступ к панели и резервным копиям
остаётся административным. В старых записях отсутствующие сведения не восстанавливаются.
Служебные machine-id/recently-used.xbel помечаются как возможные фоновые чтения;
защита и журналирование для них не отключаются. Сначала обновите Docker-сервер,
затем агенты: старый сервер не принимает расширенный формат события.


### Фильтр событий панели

Вместо отдельной галочки уведомлений используется список «События»:
- **Документы и предупреждения** (по умолчанию): файловые операции и проверки
  текста; скрыты уведомления, штатные события служб и ALLOW известных служебных
  путей. Файловые WARN/BLOCK/DENY, ошибки очереди и остановка проверки текста
  остаются видимыми.
- **Все события**: вся доступная выборка, включая уведомления и состояние защиты.
- **Файлы — все открытия**: все файловые операции, включая служебные файлы.
- **Текст и сообщения**: анализ текста, черновиков и локальных сообщений.
- **Технические события**: события служб и открытия известных служебных путей.
- **Уведомления**: только доставка уведомлений.

Каждый режим сочетается с решением, устройством, мессенджером, периодом и поиском.
Счётчик показывает отфильтрованные и все сгруппированные записи выборки.
«Сбросить фильтры» возвращает режим по умолчанию. Сводные карточки системы
по-прежнему отражают всю выборку, а не выбранный фильтр журнала.

Служебный путь определяется узким списком: machine-id, recently-used.xbel и
его временные варианты, стандартные dot-файлы оболочки/сеанса непосредственно
в /home/USER. Это подсказка интерфейса, не доказательство фонового действия.
Неизвестные пути и старые события без пути не скрываются как служебные.
Произвольные скрытые каталоги и одноимённые файлы внутри проектов не исключаются.
Данные не удаляются, политика контроля не меняется.

Фильтр включён в образ `dlp-lab-central:0.2.26`; агенты0.2.25 совместимы
для передачи событий. Для применения политик агент тоже должен быть0.2.26.
На текущем стенде сервер и основной агент обновляются через
`sudo python3 scripts/update-managed-agent.py`, затем обновляется второй агент.
