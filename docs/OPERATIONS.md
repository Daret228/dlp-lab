# Установка и эксплуатация

Актуально на 09.11.2026, версия исходников 0.2.27. Основной путь: **сервер Docker →
профиль устройства → DEB → dlp-setup**. Используйте разделы по порядку для первой установки. Для работающего агента
переходите сразу к проверке или обновлению.

## 1. Сервер

На отдельном сервере DEB агента не нужен. Нужны Docker Engine, Compose v2,
исходники проекта и HTTPS-сертификат для адреса сервера.
Следуйте [инструкции Docker](DOCKER.md). Там отдельно описаны новый сервер
и уже работающий стенд Романа — не смешивайте их команды.

## 2. Подготовить подключение (администратор сервера)

Для каждой машины создайте отдельную регистрацию по [инструкции сервера](DOCKER.md).
Объедините её с публичным CA в один профиль:

```bash
python3 scripts/build-connection.py --registration /путь/central-agent.json --ca /путь/central-ca.crt --output connection.json
```

Профиль создаётся с правами 0600, содержит только регистрацию устройства и CA.
Передайте его целевой машине доверенным способом. Не публикуйте и не используйте
один профиль на разных устройствах. Административный токен сервера туда не входит.

## 3. Установить пакет и подключить машину

Telegram должен быть установлен заранее в защищённом системном каталоге.
Для Debian 13 amd64:

```bash
sudo apt install ./dlp-lab_0.2.27_amd64.deb
sudo dlp-setup connection.json
```

Вторая команда сама выбирает пользователя рабочего стола, находит Telegram и
дополнительно Signal, записывает подключение и включает файловый контроль,
системный сеансовый компонент, отправщик и управление с сервера.
При неоднозначном выборе добавьте `--user ИМЯ`; нестандартный Telegram задайте
через `--telegram /путь`. Для проверки без изменений добавьте `--check`.

Для Debian 12 amd64 — также один пакет:

```bash
sudo apt install ./dlp-lab_0.2.27~deb12u1_amd64.deb
sudo dlp-setup connection.json
```

SQLCipher 4 включён в пакет Debian12 в собственном каталоге агента; второй DEB
не нужен, системная библиотека не заменяется. Остальные зависимости apt получает
из настроенных репозиториев Debian. Это не автономная установка без сети.
[Сборка пакетов](DEVELOPMENT.md#сборка-пакета).

Уже настроенную машину достаточно обновить через apt: подключение и политика
сохраняются, работающие компоненты перезапускаются. `sudo dlp-setup` без профиля
повторно включает настроенные службы. При ошибке возможны частичные изменения;
исправьте причину и повторите команду, не удаляя очередь и конфигурацию.

**Полностью автоматический postinst:** администратор может заранее положить
профиль в `/etc/dlp-lab/connection.json` с владельцем root и правами0600.
При установке пакет сам вызовет настройку. Нужен работающий systemd, однозначно
определяемый пользователь и установленный Telegram. В образе/chroot настройка
откладывается. Если профиль не подготовлен, пакет не угадывает адрес сервера и
не объявляет устройство подключённым — применяется обычная команда dlp-setup.
Внутри postinst apt повторно не запускается.

Сеансовая служба автоматически наблюдает доступное поле; состояние поля
отображается отдельно. Локальные базы автоматически не сканируются.

## 4. Проверить результат

На агенте:

```bash
sudo dlp-agent doctor
systemctl is-active dlp-lab-files.service dlp-lab-session.service dlp-lab-forwarder.service dlp-lab-admin-control.service
sudo journalctl -u dlp-lab-files.service -n 20 --no-pager
sudo journalctl -u dlp-lab-forwarder.service -n 20 --no-pager
```

Ожидаются `active`, событие `monitor_started`, отсутствие ошибок запуска.
`doctor` не подтверждает доставку событий. Прикрепите в своём тестовом чате
обычный и чувствительный тестовые файлы; проверьте разрешение/блокировку и новое
событие нужного устройства в панели через 15–30 секунд. Новые повторные открытия дают одну строку «Операция с файлом» с итогом
ALLOW/WARN/BLOCK; подробности остаются в локальном журнале. Старая история
сохраняется в прежнем формате. [Правила итоговой операции](CENTRAL_SERVER.md).

## 5. Повседневное управление и обновление

На агенте, перезапуск кратковременно прерывает файловый контроль:

```bash
sudo systemctl restart dlp-lab-files.service dlp-lab-session.service dlp-lab-forwarder.service
```

Обновление уже настроенного Debian 12 из каталога с новым пакетом:

```bash
sudo apt -o Dpkg::Options::="--force-confold" install ./dlp-lab_0.2.27~deb12u1_amd64.deb
sudo dlp-agent doctor
```

Для Debian 13 используйте `dlp-lab_0.2.27_amd64.deb`. Повторная регистрация
при обычном обновлении не нужна; postinst перезапускает настроенные компоненты. Серверный Docker-образ обновляется отдельно.
Из панели доступны журнал, диагностика и перезапуск файлового/текстового компонентов.
[Условия и результат команд](ADMIN_CONTROL.md#управление-с-сервера). Установка обновлений агента выполняется администратором отдельно.

Правила, исключения, удаление и резервные копии:
[обслуживание](MAINTENANCE.md).

## 6. Административный контроль текста

`dlp-lab-session.service` автоматически запускает наблюдение в активном
графическом сеансе настроенного пользователя. Пользователь не запускает CLI
и не управляет службой. [Команды и состояния](ADMIN_CONTROL.md).

Центральная веб-панель — единственная панель. Локальная панель удалена.
Проверки баз и экспортов остаются отдельными исследовательскими инструментами,
а не автоматически включаемым контролем всей переписки.

## Обновление сервера и агентов до0.2.27

Сначала обновите сервер: прежняя версия не принимает новые поля пути и причин проверки.
Для действующего стенда с мигрированным Docker и подготовленным DEB:

```bash
cd /home/roman/dlp-lab
sudo python3 scripts/update-managed-agent.py
```

После успеха обновите пакет второго агента обычной командой apt из раздела5.
Сценарий сначала проверяет сервер и затем обновляет основной агент; очередь
хранится на диске. Обычный restart контейнера не обновляет его код.
