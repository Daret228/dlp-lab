# ADR-017: обновление агентов с серверной панели

Дата: 2026-11-17. Решение принято по прямому выбору пользователя (вариант
«полностью автоматически» из трёх предложенных: с локальным подтверждением,
полностью автоматически, отложить).

## Причина

Обновление агента требовало локального действия на каждой машине (sudo-установка
или `dlp-lab-update`). Для администратора стенда удобнее управлять версиями
централизованно — из той же панели, где уже работают политики и перезапуски.

## Решение

- Панель принимает от администратора DEB `dlp-lab_<версия>_<арх>.deb`
  (до 4 МиБ, имя по строгой грамматике), сервер хранит его контент-адресно
  (sha256) и назначает конкретному устройству. Назначение создаёт задание
  `update_agent`; без свежего health с флагом `auto_update` сервер задание
  не создаёт — старые агенты канал просто не получают.
- Агент (без привилегий) скачивает пакет по своему TLS+token-каналу,
  сверяет sha256, поля `dpkg-deb` и правило «строго новее», стейджит пару
  «пакет + метаданные» в каталог брокера и передаёт брокеру фиксированное
  действие `install_update`.
- Установку выполняет выделенный oneshot-юнит `dlp-lab-update-install.service`
  (запуск `systemctl start --wait` от брокера): песочница брокера не подходит
  для apt/dpkg, а отдельный юнит держит привилегированную поверхность
  минимальной и явной. Установка идёт под общим lock `dlp-lab-update.lock`
  (взаимная блокировка с ручным `dlp-lab-update`), `--force-confold`,
  ожидание блокировки dpkg ограничено 60 c.
- Самообновление в момент установки перезапускает forwarder и брокер:
  обрыв связи трактуется как «исход неизвестен» — задание не закрывается
  ошибкой, а повторяется после рестарта; при уже установленной версии
  агент сразу отвечает выполненным. Повтор задания по ID не исполняется
  дважды (журнал действий брокера).
- Модель доверия сдвигается: право установки пакета получает администратор
  сервера (токен панели), а не только локальная группа `dlp-updaters`.
  Это отражено в threat model и ADMIN.

## Ограничения

- Компрометация сервера или токена администратора позволяет подменить код
  агентов; пакеты криптографически не подписаны (как и весь проект) —
  целостность обеспечивают TLS, sha256 и проверка полей DEB.
- Битый пакет, ломающий forwarder, обрывает и канал обновления: восстановление
  только локальными средствами (dpkg/dlp-lab-update).
- Администратор сам выбирает пакет под ОС устройства (deb13/deb12) — сервер
  версию ОС не сверяет, проверяется только архитектура при установке.
- Первый переход на 0.2.37 выполняется вручную (сервер первым, затем агенты);
  панель начинает обновлять агенты с версий 0.2.37+.
