# 010. Ограниченное изменение политики из панели

Дата: 2026-10-15. Статус: реализовано.

Панель изменяет только thresholds, on_error и sensitive_alerts.enabled в
фиксированном config/policy.yaml. Режим новых категорий rules, действие WARN.
Остальные значения политики сохраняются; YAML сериализуется заново без комментариев.
Произвольных путей, правил, команд и автоматического перезапуска API не принимает.

GET /api/policy показывает только редактируемые параметры и SHA256 версии.
POST /api/policy/preview проверяет параметры и возвращает изменения.
POST /api/policy повторно проверяет параметры и ожидаемую версию, валидирует
полную новую политику существующим load_policy, сохраняет исходные байты в
build/policy-backups (файл 0600), заменяет конфигурацию через os.replace.
Без изменений запись отсутствует. При ошибке backup/replace исходный файл сохраняется.
Резервные копии не удаляются автоматически, откат пока ручной.

POST требует ключ процесса, точный Origin/Host, JSON с уникальными ключами,
Content-Length до 8192 байт, без Transfer-Encoding. Тайм-аут чтения тела 5 секунд.
Версионный контроль и mutex предотвращают потерю обычных параллельных правок;
это не защита от враждебного процесса того же Unix-пользователя, способного менять
каталог между проверкой и replace. Панель не является сервером для сети/многих пользователей.

В интерфейсе сохранение доступно после просмотра изменений. Работающие процессы
не перечитывают политику: показана политика диска, а не подтверждённая конфигурация
процесса. Управление жизненным циклом модулей остаётся отдельным следующим этапом.
