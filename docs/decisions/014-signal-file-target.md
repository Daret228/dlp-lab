# ADR-014: второй файловый процесс Signal (2026-10-23)

Сохраняем Telegram как обязательную цель для совместимости установленного формата.
В защищённую gateway-конфигурацию добавляется необязательное поле signal с
абсолютным путём. Дубли ключа, неправильные пути и одинаковые пути двух клиентов
отклоняются. Без signal поведение соответствует прежней Telegram-конфигурации.

Native broker проверяет UID и точные путь/device/inode каждого клиента.
Python получает файловые дескрипторы только выбранных процессов; общий fanotify
FD остаётся у broker. Оба клиента используют прежнюю ограниченную очередь,
таймауты и подтверждения enforcement. Неизвестный процесс или изменившийся inode
не превращается в глобальный запрет: это прежний ALLOW с отчётом о пробеле.

В worker передаются DLP_TARGET_EXECUTABLE и DLP_SIGNAL_EXECUTABLE из доверенной
конфигурации после очистки окружения. Перед ready-handshake проверяется наличие
обоих путей в соответствующих именованных адаптерах processes.yaml. monitor_started
включает controlled_messengers; режим all не применяется. Поддержка другого
исполняемого файла helper/портала автоматически не подразумевается.

Сохраняются текущие исключения, включая .config с профилем Signal. Это не анализ
локальной истории. Временные файлы и способы прикрепления требуют ручной проверки.

Установщики: scripts/update-fanotify-access.sh --signal PATH для лаборатории;
пакетный dlp-lab-configure --signal PATH создаёт согласованные host-настройки.
При --replace без --signal пакетный configurator убирает Signal и сбрасывает
исключения, как описано в README.Debian. Debconf остаётся Telegram-only.
Новые исходники не обновляют установленный root-owned gateway автоматически.

Проверено: C build с -Werror, native harness узнаёт второй executable, отклоняет
другой UID/путь и заменённый inode. Парсер принимает старую конфигурацию и новый
ключ, отклоняет повторы/совпадения. Worker отказывает до handshake при отсутствии
правильного Signal adapter. Полный suite: 209 тестов, 207 прошли, 2 opt-in skipped.
Пакет 0.2.3 собран с --local-deps; новая версия не установлена и не проходила
повторный dpkg lifecycle. Живой DENY Signal пока не проверен.

## Уточнение 2026-10-23: служебные файлы fontconfig

Signal открывал системные кэши шрифтов; on_error=BLOCK вызывал 60 лишних DENY.
Worker теперь допускает только защищённые root-owned файлы стандартного формата
имён непосредственно в /var/cache/fontconfig. Проверяются права всех родителей,
regular FD, совпадение inode/device с несимлинковой записью, nlink=1 и отсутствие
group/world write. Пользовательские файлы или одноимённый файл в другом каталоге
проверяются как прежде. Исключение видно в monitor_started.operational_exceptions.
Это сужение области анализа для системных служебных файлов, не успешный анализ
их содержимого. Таймер/urgency уведомлений не заменяет исправление причины DENY.
