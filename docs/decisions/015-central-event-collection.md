# 015. Центральный журнал и автономные агенты

Дата: 2026-10-27. Пользователь согласовал начало реализации агент-серверной
архитектуры: регистрация устройств и сбор событий, затем политики.

## Решение

Анализаторы, предупреждения и fanotify остаются локальными. Отдельный opt-in
процесс читает journald выбранных DLP units и отправляет только строгую проекцию
событий. Он не выполняется в пути обработки FAN_OPEN_PERM. Сетевые ошибки не
влияют на решение локального анализатора. Произвольные тексты, категории, пути,
ключи, идентификаторы чатов и причины ошибок не передаются.

Сервер: Python stdlib HTTP(S), SQLite, отдельная веб-страница только для просмотра.
Администратор локальной CLI создаёт случайный токен устройства и конфигурацию
0600; в БД сервера хранится SHA256 токена. Токен не передаётся аргументом команды
и не печатается. Доставка конфигурации на машину — отдельный административный
шаг; открытой самостоятельной регистрации через сеть нет. Токен администратора
отличается от токенов агентов; агент не может читать общий журнал. Есть отзыв
токена без удаления исторических событий. Административный токен вводится в
страницу, не сохраняется в URL или localStorage. Доверенные устройства могут
сообщать ложные результаты: это не механизм аттестации.

TLS обязателен вне literal loopback; верификация сертификата штатная, редиректы
отправщика запрещены. Первое испытание только localhost. Для сети нужен сертификат
доверенного CA и закрытый ключ сервера. Встроенный сервер — исследовательский MVP,
без промышленной защиты от DoS, ролей/SSO, ротации административного токена через UI.

## Очередь и полнота

SQLite очередь и journald cursor коммитятся атомарно. ID события детерминирован
из ID агента, источника и cursor. Сервер подтверждает принятые IDs только после
commit; повторный запрос не создаёт дубликатов. Очередь привязана к серверу и ID
агента. До 100 событий за запрос, до 500 записей за проход сборщика, очередь до
10000 событий. При заполнении сбор новых записей приостанавливается, отправка
оставшейся очереди продолжается. Сервер пока не имеет автоматического retention.
При первом запуске читаются последние 5 минут, затем сохранённый cursor. Потеря
или очистка journald до сбора может привести к потере событий. Не заявляем
гарантированную полноту. Просроченный cursor требует диагностики; автоматического
сброса с молчаливой потерей истории нет.

User/system журналы запускаются разными процессами и с разными каталогами очереди.
Для system journal нужны уже выданные права чтения. Модуль не расширяет права сам.
Отдельные CLI проверки попадут на сервер только если запущены через журналируемую
службу; произвольные файлы профиля/экспорты сборщик не читает.

## Следующие этапы

Проверка с настоящей второй Linux-машиной по TLS; отдельные unit и DEB для сервера
и отправщика; управление версиями политик; retention, метрики очереди/доставки,
состояние модулей. Последняя связь устройства означает связь отправщика, не
доказательство работы всех анализаторов. Локальная панель на 8765 сохраняется;
центральная на 8766 не управляет модулями и политиками.


Актуализация 06.11.2026: локальная панель 8765 удалена в 0.2.18 по требованию пользователя. Веб-интерфейс остаётся только у центрального сервера; пользовательские модули управляются CLI.
