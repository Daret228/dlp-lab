# 011. Управление тестовыми мониторами из локальной панели

Дата: 2026-10-16. Статус: реализовано.

POST /api/control принимает только component files/text и action start/stop.
Проверки ключа, Host/Origin, размера тела и JSON общие с политикой. Произвольные
команды, units, пути, длительность и маркеры не принимаются. Используются
существующие service.launch_command и фиксированные пользовательские systemd units.
Запросы сериализованы; команды ограничены тайм-аутом 15 секунд каждая.

Файлы: установленный gateway, direct_children /var/lib/dlp-lab/watch, фильтр
мессенджеров. Текст: DLP_TEST, 120 секунд, observe_only. Нет запуска local/export:
для них нужны отдельные условия и параметры. Полномочия sudo не расширены.

UI предварительно показывает действие и область, смена выбора отменяет подготовку.
После операции сбрасывается кеш статуса. Ошибки команд не раскрывают stderr;
при неопределённом результате пользователь должен проверить статус и журнал.
Ответ запуска содержит SHA256 политики на момент запроса, но не утверждает, что
именно её загрузил процесс. Подтверждение применённой версии остаётся будущей задачей.
Состояние процесса не доказывает готовность; для этого нужны события журнала.

Проверены реальные запуск из браузера → monitor_started (uid 1000) → остановка
через API → inactive. Файлы не прикреплялись, текстовый монитор не запускался.

## Подтверждение загрузки политики — 2026-10-16

После создания анализатора monitor/text-monitor пишет policy_loaded с SHA256
ровно тех байтов, которые были прочитаны и разобраны валидатором. Панель связывает
событие с unit и доверенным journald _SYSTEMD_INVOCATION_ID, сравнивая его с
InvocationID из systemctl. Только active/activating текущий запуск получает
подтверждённую версию; остановленный модуль не наследует подтверждение.
Версия сравнивается с валидной политикой на диске. Несовпадение требует перезапуска.
Старое событие другого запуска, отсутствие/обрезка журнала или неизвестный
InvocationID не дают подтверждения. Используется текущая выборка периода/1000 записей,
кеш 5 секунд; это не постоянный реестр конфигураций. policy_loaded не означает
готовность fanotify или успешную привязку поля Telegram.
