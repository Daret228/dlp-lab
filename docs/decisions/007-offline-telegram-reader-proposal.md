# ADR-007: внешний анализатор копии tdata

Дата: 2026-10-09. Статус: пользователь явно разрешил описанную обработку копии
собственного тестового хранилища и локального ключа, без подбора пароля и
извлечения сетевых ключей. Подтвердил отсутствие локального код-пароля.
Telegram не изменять: пользователь прямо отклонил отдельную
сборку. eXpress недоступен. Отсутствие API не доказывает невозможность внешнего
чтения собственного хранилища.

## Возможный путь

Внешняя программа открывает выбранную копию собственного тестового tdata,
проверяет формат и целостность контейнеров, использует предоставленный владельцем
известный локальный код-пароль (либо явно подтверждённое отсутствие такого кода),
восстанавливает локальный ключ в памяти и разбирает ограниченный набор записей.
Telegram остаётся неизменённым. Это обработка зашифрованных локальных данных,
а не ещё один экспорт и не анализ stat. Совместимость с установленной версией
и наличие нужных записей пока не проверены.

Основание: [Domain::startModern, Telegram v7.2.8](https://raw.githubusercontent.com/telegramdesktop/tdesktop/v7.2.8/Telegram/SourceFiles/storage/storage_domain.cpp)
читает соль и защищённый локальный ключ, использует passcode, проверяет результат
и обрабатывает локальные сведения об аккаунтах. Эти операции не выполнялись на
профиле пользователя. Источник показывает устройство чтения, не готовый API.

## Почему нужна отдельная договорённость

В первоначальном запросе пользователя (прикреплённый «Вставленный текст.txt»,
раздел анализа локальных данных) прямо указано: «Не пытаться обходить
криптографическую защиту». В текущем контексте также исключена расшифровка
защищённого tdata. Чтение владельцем с известным паролем следует отличать от
подбора пароля, но разрешение на обработку локального ключа ещё не было дано.
Предлагается узко разрешить именно эту обработку собственного тестового профиля.
Это не системный запрет на исследование, а необходимость уточнить область работ.

## Границы предлагаемого эксперимента

1. Сначала реализация и проверка на искусственных контейнерах: формат, лимиты,
   контроль целостности, неверный пароль, повреждения, неизвестная версия.
2. После согласия — копия отдельного собственного тестового профиля при закрытом
   Telegram; исходный профиль не менять. Не копировать рабочие сессии без нужды.
3. Локальный пароль вводится пользователем в скрытом терминальном приглашении,
   не в чате, аргументах команды, переменных окружения или журнале. Подбора нет.
4. Локальный ключ используется только для чтения требуемых записей в памяти,
   не выводится и не записывается отдельно. Сетевые ключи авторизации/сессии не
   извлекать, не экспортировать, не использовать для входа; сеть читателю не нужна.
5. Первая цель — один заранее известный искусственный черновик. Получить текст
   в памяти, передать ContentAnalyzer, вывести только решение и факт совпадения
   с тестовым ожиданием. Полную историю заранее не обещать.
6. Затем отдельно изучить необходимые метаданные вложений; неизвестный формат
   означает явную ошибку, не ALLOW. Повреждения не исправлять в профиле.

## Критерий успеха

Без изменения Telegram из дискового контейнера выбранной копии прочитан
искусственный черновик; проверено его происхождение и совпадение, анализатор
выдал ожидаемое решение. Это подтверждает чтение данного вида записи и версии,
не всех сообщений или всех мессенджеров. При отказе от обработки локального ключа
этот путь исключается; старые JSON/stat-инструменты не становятся заменой базы.

## Реализация и приёмка 2026-10-09

Разрешение получено явно. Reader реализован; критерий первой цели выполнен:
искусственный черновик прочитан из зашифрованной копии закрытого Telegram,
совпадение подтверждено, результат BLOCK/0.8/complete=true. Ключи/текст не
журналировались. 9 новых тестов; полный прогон 74, прошли 72, opt-in пропущены 2.
