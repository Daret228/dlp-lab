# Демонстрация прототипа для ВКР

Дата: 2026-10-06. Выполнять от roman в обычном терминале графического сеанса,
без sudo перед scripts/dlp. Предварительно установлен ограниченный gateway.

## 1. Состояние и общий журнал

```bash
cd /home/roman/dlp-lab
./scripts/dlp agent status
./scripts/dlp agent logs --follow
```

Последняя команда показывает события в реальном времени; Ctrl+C прекращает только
просмотр. Остальные команды выполнять во втором терминале из того же каталога.
Журнал содержит прежние опыты: различать их по timestamp и сообщениям запуска.
Статус учитывает только управляемые запуски. Перед демонстрацией завершить свои
старые ручные monitor/text-monitor, если они остались запущены.

## 2. История сообщений — разовая проверка

Без подготовки Telegram доступен искусственный пример:

```bash
./scripts/dlp agent export --file examples/telegram-export-synthetic.json
./scripts/dlp agent logs --lines 15
```

Ожидается ALLOW/WARN/BLOCK, summary: analyzed_texts=3, analysis_failures=0.
Вложение без текста и service пропущены со счётчиками. После завершения status
показывает экспорт остановленным: это штатное завершение разового задания.
BLOCK — классификация истории, не блокировка отправки.
Для собственного экспорта заменить путь на явно выбранный result.json.

## 3. Контроль файлов Telegram

```bash
./scripts/dlp agent start files
./scripts/dlp agent status
./scripts/dlp agent logs --lines 15
```

Ожидаются работающий процесс и новое событие monitor_started, uid=1000,
filter_mode=messengers. Если их нет — открыть журнал и устранить причину;
одно сообщение «Процесс запущен» ещё не подтверждает готовность.

В собственном тестовом чате вручную выбрать через скрепку → Файл:

1. `/var/lib/dlp-lab/watch/dlp-public-demo.txt` — доступ разрешён.
2. `/var/lib/dlp-lab/watch/dlp-secret-demo.txt` — доступ запрещён.

Файлы уже подготовлены на стенде. Отправка не нужна. В журнале проверить
file_access_attempt, messenger=telegram, enforcement=ALLOW/DENY.
Повторные open возможны. В режиме messengers обычный cat не является проверкой
блокировки: он вне выбранной области. Изображения не подходят для проверки
текстовых правил: распознавание содержимого медиа не реализовано.

```bash
./scripts/dlp agent stop files
```

После остановки файловое наблюдение и соответствующий запрет прекращаются.

## 4. Наблюдение за текстовым полем

Сохранить нужные черновики; полностью выйти из Telegram. Запустить:

```bash
QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1 /usr/bin/telegram-desktop
```

В своём тестовом чате набрать `DLP_TEST` и оставить окно видимым. В другом терминале:

```bash
cd /home/roman/dlp-lab
./scripts/dlp agent start text --marker DLP_TEST --seconds 120
./scripts/dlp agent logs --follow
```

Ожидается text_monitor_started: поле найдено. До этого процесс может ждать 30 секунд;
при отсутствии/неоднозначности поля он завершится с ошибкой и объяснением в журнале.
После привязки менять черновик: обычный текст, test@example.com, искусственная
секретная фраза. Ожидаются draft_analysis с ALLOW/WARN/BLOCK. Отправлять не нужно.
Пустое поле не подтверждает отправку. Уведомления зависят от desktop-сеанса.

Примерно через 120 секунд после привязки монитор завершится. Досрочно:

```bash
./scripts/dlp agent stop text
```

Отправка текста не запрещается: observe_only, send_blocked=false.

## 5. Завершение

```bash
./scripts/dlp agent stop
./scripts/dlp agent status
```

Все три управляемых компонента должны быть остановлены. Логи сохраняются согласно
настройкам journald хоста. Автозапуска нет. Не заявлять демонстрацию защищённой
промышленной службы или универсального контроля всех мессенджеров.

## Что фиксировать в ВКР

Для каждого опыта: источник, ожидаемое решение, фактическое решение, реальное
действие (если применимо), ошибка/ограничение. Без переписки, имён чатов и личных ID.
Отдельно перечислить detection и prevention. Обнаруженные совпадения сами по себе
не доказывают утечку; отсутствие совпадений не доказывает безопасность.

## Локальное хранилище и предупреждения (2026-10-09)

Для реального опыта оставьте в своём тестовом чате черновик
`DLP_STORAGE_TEST коммерческая тайна` и полностью выйдите из Telegram.
Запустите от обычного пользователя:

```sh
cd /home/roman/dlp-lab
scripts/dlp agent local --profile-closed --no-passcode \
  --expected-path /home/roman/dlp-lab/examples/DLP_STORAGE_ATTACHMENT_TEST.txt
scripts/dlp agent logs --lines 30
```

Ожидаются результат черновика, файловые метаданные, предупреждение и итог
local_check_finished. Нужен именно отмеченный черновик; его отсутствие — ошибка,
а не ALLOW. Файловая запись может отсутствовать и не доказывает отправку.
Если нужен только черновик, опустите --expected-path. Telegram оставляйте закрытым
до завершения команды. Для профиля с код-паролем эта фоновая команда не подходит.

Проверка только механизма предупреждения на искусственном тексте:

```sh
scripts/dlp agent notification-test
scripts/dlp agent logs --lines 15
```

notification_delivery/accepted означает принятие службой рабочего стола; появление
окна проверяется визуально. После разового задания статус inactive нормален — итог
смотрите в журнале. Оба новых unit входят в agent status/logs/stop all.
