# Разработка и проверка

Этот раздел для разработчика. Для установки готового агента используйте
[эксплуатацию](OPERATIONS.md).

Из корня проекта, с установленными зависимостями из `debian/control`:

```bash
make test
make build
./scripts/build-deb.sh
```

`make test` выполняет тесты Python. Привилегированные тесты и SQLCipher требуют
своего окружения; пропуски не считайте успешными проверками этих механизмов.
`make build` собирает native-компоненты. Сборка DEB также выполняет тесты.
Версия ОС сборки должна соответствовать целевой ОС агента.

Ручной анализ из исходников:

```bash
./scripts/dlp analyze --text 'Обычная встреча'
./scripts/dlp analyze --text 'коммерческая тайна'
```

Файловый монитор из исходников не запускайте одновременно с установленной
службой. Для ручного запуска установленного файлового контроля:

```bash
sudo systemctl stop dlp-lab-files.service
sudo dlp-lab-run-files
# После Ctrl+C верните системную службу:
sudo systemctl start dlp-lab-files.service
```

Проверка Docker в отдельном временном проекте:

```bash
sudo python3 scripts/test-docker.py
```

Она создаёт тестовые контейнеры и данные, проверяет HTTPS, аутентификацию,
приём события и сохранение состояния; рабочий сервер не переносит.

Карта исходников: `native/` — файловый перехват; `src/dlp/` — анализ,
адаптеры, сервер; `src/dlp/ml_assets/` — модель; `tests/` — тесты;
`packaging/` и `debian/` — пакет и службы; `docker/` — серверный контейнер;
`data/ml/` — наборы и отчёты ML. Результаты экспериментов находятся в
`docs/research/`, журнал решений и проверок — в `docs/PROJECT_CONTEXT.md`.
