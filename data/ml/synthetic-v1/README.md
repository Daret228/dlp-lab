# Стартовый набор для локального ML

Дата: 2026-10-13. Версия: synthetic-v1. Статус: предварительная авторская разметка,
не проверенная пользователем. Все тексты написаны искусственно для этого проекта;
экспорты, локальный профиль Telegram и реальные документы не использовались.
Пароли/токены вымышлены и не дают доступа к системам. Числовые реквизиты придуманы,
не проверялись по реестрам и не предназначены для платежей или идентификации.

## Назначение

Проверить будущий конвейер обучения для трёх согласованных категорий. Это набор
для начального эксперимента, не промышленный датасет и не доказательство качества.
Обучения и подключения ML к агенту на этом этапе нет; рабочая политика не менялась.

| Файл | Всего | На каждую категорию, включая обычные тексты |
|---|---:|---:|
| train.json | 64 | 16 |
| dev.json | 16 | 4 |
| test.json | 16 | 4 |
| review.json | 12 | Спорные случаи, исключены из трёх выборок |

В каждой из основных выборок четыре группы: financial, passport, credentials
и обычный текст (пустой массив labels). Сценарии написаны отдельно; числовые
подстановки одного шаблона не использовались для увеличения числа примеров.
Разбиение фиксированное. Будущие варианты одного сценария должны сохранять
его group_id и попадать в ту же выборку. Проверка group_id не доказывает отсутствие
семантического сходства; отдельного независимого автора теста пока нет.

## Предварительные правила разметки

- financial: конкретные платёжные реквизиты, индивидуальные зарплаты/долги/доходы,
  явно внутренние финансовые показатели. Обычная цена и опубликованный отчёт
  сами по себе не положительный пример.
- passport: значения реквизитов с явным паспортным контекстом. Упоминание паспорта
  и пустая форма без значений не положительный пример.
- credentials: конкретное значение пароля, секрета API, токена, резервного кода
  или пара логин/пароль. Один логин, сообщение об ошибке и маска секрета пока
  отрицательные примеры; эти границы вынесены на согласование.
- labels=[] означает отсутствие выбранных признаков по этой разметке, а не
  универсальную безопасность текста. Например, другие персональные данные
  не покрыты этими тремя категориями.

Несколько labels допустимы схемой; смешанные примеры пока находятся только
в review.json. Модель на одних основных выборках ещё не проверяет совместные категории.
Условные строки доступа размечены по форме передаваемого секрета: модель не может
проверять, действителен ли пароль. Вопрос об исключении учебных примеров открыт.
Решения ALLOW/WARN/BLOCK не являются метками датасета: их назначит отдельная политика.

## Формат и использование

Каждая запись: id, group_id, split, text, labels, rationale, source,
annotation_status. Для обучения подавать только text, целевой ответ — labels.
Не подавать id, rationale, group_id или другие служебные поля: они раскрывают класс.
Train — обучение; dev — выбор параметров/порогов; test — окончательная проверка
после фиксации подхода. Не выбирать параметры по результатам test. При многократной
настройке на этом тесте потребуется новая независимая выборка.

```sh
python3 scripts/validate-ml-corpus.py
```

Проверяются схема, категории, точные нормализованные дубликаты и отсутствие
пересечения групп между выборками. Содержательная правильность меток требует
человеческой проверки. Для спорных случаев предназначен REVIEW.md.

## Ограничения и следующий этап

96 примеров недостаточно для надёжной оценки рабочих условий. В тесте только
4 примера каждой группы: одна ошибка сильно меняет показатель. Тексты короткие,
в основном русские; нет полноценного набора ошибок OCR, транслита, длинных документов,
обфускации и разных доменов. Положительные секреты часто содержат Example/sample,
паспортные серии и карты — искусственные нули. Модель может выучить эти артефакты.
Это нужно проверять на отдельном более разнообразном наборе, а не выдавать высокий
результат на синтетике за защиту реальных данных.

После согласования границ расширить набор, добавить смешанные классы и независимые
проверочные сценарии. Затем обучить компактный baseline и сравнить его с правилами:
precision/recall/F1 по каждой категории, ложные тревоги обычных текстов, время анализа.
Сначала оценка offline; подключение ML и выбор режима реакции — отдельный этап.
