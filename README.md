# DLP Lab для Linux

Агент контроля утечек для Telegram Desktop и Signal Desktop, разработанный
в рамках ВКР. Анализ выполняется на рабочей машине, события доступны администратору
в центральной веб-панели.

## Как устанавливать

| Куда | Что устанавливается | Как |
| --- | --- | --- |
| Сервер администратора | Центральная панель и хранилище событий | Docker Compose + HTTPS-сертификат |
| Рабочая машина | Агент и службы systemd | DEB + `sudo dlp-setup connection.json` |

На клиенте: установить DEB своей версии Debian, затем выполнить
`sudo dlp-setup connection.json`. Индивидуальный профиль подключения готовит
администратор. Команда настраивает и запускает службы. При заранее размещённом
профиле настройка выполняется прямо из postinst.

**Начните с [установки и эксплуатации](docs/OPERATIONS.md).**
Сервер: [Docker — новый сервер и текущий стенд](docs/DOCKER.md).

## Что работает

- Контроль открытия файлов Telegram и Signal через fanotify; анализ текста, PDF и DOCX.
- Правила и ML-модель для чувствительных данных; ML-предупреждения.
- Наблюдение за тестовым полем ввода через AT-SPI, уведомления и журнал.
- Проверка локального черновика Telegram, JSON-экспорта и сохранённых текстов Signal.
- Сбор событий нескольких устройств по HTTPS, группировка повторных открытий,
  диагностика и перезапуск компонентов через панель.

Файловый BLOCK означает запрет открытия. Текстовый BLOCK — результат анализа,
не запрет отправки. Полная локальная история Telegram не читается. Автоматический выбор поля в сеансе требует проверки на установленном клиенте.
Обновление агентов из панели не реализовано.

## Текущее состояние

Версия исходников **0.2.22** добавляет настройку установленного агента одной
командой и автоматический postinst для заранее подготовленного профиля.
Сервер0.2.21 совместим; его обновлять для этой функции не требуется.
На чистом Debian12 отдельно требуется зависимость SQLCipher4 — см.
[установку](docs/OPERATIONS.md). Результаты проверок находятся в
[контексте проекта](docs/PROJECT_CONTEXT.md).
